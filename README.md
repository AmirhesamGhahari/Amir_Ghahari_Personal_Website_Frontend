## What Is This Project?

This is a **personal portfolio website** for Amir Ghahari. The design was built
visually in **Plasmic** — a drag-and-drop website builder that generates real code.
That generated code runs on **Next.js**, which is a popular framework for building
websites with React and JavaScript/TypeScript.

Think of it like this:
- **Plasmic** = the design tool (like Figma, but it generates real working code)
- **Next.js** = the engine that turns that code into a real website
- **React** = the underlying library Next.js is built on, for building UIs

---

## How a Website Works in This Stack

```
Browser (Chrome / Safari)
        ↑
  Next.js serves the pages
        ↑
  React components render HTML
        ↑
  Plasmic generated the component code
        ↑
  You designed it in Plasmic's visual editor
```

---

## The Edit → Preview → Deploy Flow

```
1. Make design changes in Plasmic studio (in browser)
            ↓
2. Run: npx plasmic sync
   (downloads updated generated code into components/plasmic/)
            ↓
3. Run: npm run dev
   (starts a local preview at http://localhost:3000)
            ↓
4. Run: npm run build
   (generates the out/ folder with plain static HTML files)
            ↓
5. Upload the out/ folder to your hosting (S3, Netlify, GitHub Pages, etc.)
```

## File & Folder Reference

### `package.json` — The Shopping List

Lists every external library the project depends on. Like a recipe ingredient list.
When you run `npm install`, it reads this file and downloads everything into `node_modules/`.

Key dependencies:
- **`next`** — the web framework that runs your site
- **`react`** and **`react-dom`** — the UI library React is built on
- **`@plasmicapp/loader-nextjs`** — the bridge between Plasmic and Next.js
- **`@ant-design/icons`** — icon library (Ant Design icons used in your design)

---

### `node_modules/` — The Downloaded Libraries

A huge folder (383 sub-folders!) containing all the code from the libraries listed
in `package.json`. **You never edit anything here.** It is auto-generated and
should not be committed to version control (it's in `.gitignore`).

---

### `pages/` — Your Website's URL Routes

This is one of the most important folders. In Next.js, **each file in `pages/`
automatically becomes a URL on your website**. No configuration needed.

| File | URL it becomes |
|---|---|
| `index.tsx` | `/` (the home page) |
| `about-me.tsx` | `/about-me` |
| `skills.tsx` | `/skills` |
| `work-experience.tsx` | `/work-experience` |
| `resume.tsx` | `/resume` |
| `contact.tsx` | `/contact` |
| `contact-2.tsx` | `/contact-2` |
| `home-2.tsx` | `/home-2` |
| `plasmic-host.tsx` | `/plasmic-host` (special — see below) |

Each page file is intentionally simple — it just renders a `Plasmic___` component
that holds all the actual visual design. For example, `pages/index.tsx` renders
`<PlasmicHome />` and that's it. The real layout lives in the generated Plasmic file.

#### What is `plasmic-host.tsx`?
This is a special page that lets the Plasmic visual editor connect to your running
local app. When you have `npm run dev` running and open Plasmic studio, Plasmic
communicates through this page to show your live components inside their editor.
You don't use it directly as a visitor — it's a dev tool.

---

### `components/` — Reusable UI Pieces

This folder has two very different types of files:

#### Type 1: Your Editable Wrapper Components (top-level `.tsx` files)

Files like:
- `WebsiteHeader.tsx`
- `WebsiteFooter.tsx`
- `Button.tsx`
- `Modal.tsx`
- `ContactSectionFooterTop.tsx`
- etc.

These are **yours to edit freely**. Each one is a thin wrapper around the
Plasmic-generated version of the same component. The wrapper is where you add
real behavior — click handlers, form submissions, data fetching, etc.

Example: `WebsiteHeader.tsx` wraps `PlasmicWebsiteHeader`. If you want a menu
item to navigate to a new page when clicked, you'd add that logic here.

#### Type 2: `components/plasmic/` — Auto-Generated Code (Never Edit This)

This entire subfolder is 100% machine-generated by Plasmic's sync tool. It
contains the actual layout, styles, and visual structure of every component.

**Never edit these files manually.** If you change your design in Plasmic and
run `npx plasmic sync`, these files get completely overwritten and your edits
would be lost.

Inside `components/plasmic/amir_ghahari_website/` you'll find pairs like:
- `PlasmicHome.tsx` + `PlasmicHome.module.css`
- `PlasmicAboutMe.tsx` + `PlasmicAboutMe.module.css`
- `PlasmicWebsiteHeader.tsx` + `PlasmicWebsiteHeader.module.css`
- etc.

The `.tsx` file is the structure (HTML layout in React), the `.module.css` file
is the visual styles (colors, fonts, spacing) for that component only.

There are also subfolders for third-party Plasmic libraries:
- `antd_5_hostless/` — Ant Design components
- `react_aria/` — Accessible UI primitives
- `plasmic_nav/` — Navigation components
- etc.

---

### `styles/` — Global CSS Styles

- **`globals.css`** — CSS rules that apply to your **entire** website.
  Currently sets background color, font, link appearance, and basic resets.
  This is where you'd add site-wide style changes.

- **`Home.module.css`** — Styles scoped only to the home page.
  Currently mostly empty since Plasmic handles the styling for you.

#### What is CSS?
CSS (Cascading Style Sheets) is how you control the visual appearance of HTML.
Colors, fonts, sizes, spacing, layout — all controlled with CSS.

---

### `out/` — The Final Built Website

When you run `npm run build`, Next.js converts all your TypeScript/React code
into plain `.html` files that any web server can serve — no special software needed.

The `out/` folder is the result. You'll see:
- `index.html` — your home page
- `about-me.html`
- `skills.html`
- etc.

**This is what you upload to your hosting provider.** Visitors' browsers download
these HTML files directly.

---

### `plasmic-init.ts` — The Plasmic Connection

This file connects your code to your Plasmic project using a project ID and a
token (like a username + password for your Plasmic account). It tells the app
"fetch my design from Plasmic's servers using these credentials."

The `preview: true` line means it uses the unpublished draft version of your
design (good for development — you can see changes without publishing first).
For a production deployment, you'd set this to `false`.

---

### `plasmic.json` and `plasmic.lock`

Automatically managed by Plasmic's sync tool. They record which version of your
design was last downloaded — similar to how `package-lock.json` locks library
versions. Do not edit these by hand.

---

### `next.config.mjs` — Next.js Settings

Key settings:
- **`output: "export"`** — tells Next.js to generate static `.html` files
  instead of requiring a Node.js server. This lets you host the site on S3,
  GitHub Pages, Netlify static hosting, etc.
- **`images: { unoptimized: true }`** — required for static export because
  the built-in Next.js image optimizer needs a server to run.

---

### `tsconfig.json` — TypeScript Configuration

TypeScript is JavaScript with type safety — it catches bugs before you run your
code by checking that you're using values correctly. This file configures how
TypeScript works in the project.

The important line: `"@/*": ["./*"]` — this lets you write:
```ts
import x from "@/components/WebsiteHeader"
```
instead of the messy relative path:
```ts
import x from "../../components/WebsiteHeader"
```

---

### `next-env.d.ts` — TypeScript Type Declarations for Next.js

Auto-generated by Next.js. Tells TypeScript about Next.js-specific features.
Never edit this file.

---

### `public/` — Static Assets

Files in this folder are served directly by the browser at the root URL.
For example, `public/favicon.ico` is accessible at `yoursite.com/favicon.ico`.
This is where you put images, PDFs (like your resume), or other files that
aren't code.

---

## What `.tsx` Files Are

`.tsx` = TypeScript + JSX.

**TypeScript** is JavaScript with type safety (catches bugs at write-time).
**JSX** is a way to write HTML-like markup inside JavaScript/TypeScript code.

Example:
```tsx
function MyPage() {
  return (
    <div>
      <h1>Hello Amir</h1>
      <p>This is my portfolio.</p>
    </div>
  );
}
```

That HTML-looking code inside the function is JSX. React converts it into real
browser HTML. The file extension `.tsx` tells the tools "this TypeScript file
contains JSX."

## The Golden Rule

> **Plasmic owns the look. You own the behavior.**

- Visual design changes → edit in Plasmic studio → run `npx plasmic sync`
- Logic, data, interactivity, behavior → edit files in `pages/` and top-level `components/`
